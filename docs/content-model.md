# Firestore content model

Each document in `entries` has `type` (`blog`, `portfolio`, `project`, `credit`), `status` (`draft` or `published`), lowercase hyphenated `slug`, integer `revision`, `en` and `vi` objects with `title`, optional `summary`, and Markdown `body`, plus Firestore `createdAt` and `updatedAt` timestamps. Blog entries require a `date` in `YYYY-MM-DD` format; portfolio/project entries require integer `year`; credits require `role`. Optional organization/presentation fields are `sortOrder`, `featureimage` (a local site path or HTTPS URL), `medium`, `category`, and HTTPS `externalUrl`. `tags`, `youtubeUrl`, and `soundcloudUrl` are also optional. The editor increments `revision` on each save, and publish requests record the revision built.

Unpublish a live entry and wait for the build to succeed before deleting it. The editor and Firestore rules block deletion while the entry is published, queued, or has a failed unpublish, so the public Hugo copy cannot be orphaned by a database-only delete. The backend stores `publishedContent` only after a successful Hosting deploy; later builds use that snapshot while edits are pending or have failed, and use the queued revision only for its own publish build. Clients cannot write publish requests or deployed snapshots. Run the regression checks with `npm --prefix admin test` and `npm --prefix functions test`.

Firestore permits access only to authenticated users with the `admin: true` custom claim. Grant it to the owner's existing Auth UID with `GOOGLE_APPLICATION_CREDENTIALS=... OWNER_UID=... npm run set:owner-claim`. The Admin SDK script preserves other claims; the owner signs out and back in to refresh the ID token. Until then, access fails closed. Enable Email/Password sign-in in Firebase Authentication before the first editor login. When deploying the callable, set the `OWNER_UID` parameter to this same UID; the function checks both the UID and claim.

The exporter includes published entries only and writes paired English and Vietnamese Markdown files under exporter-owned `content/<section>/cms/` folders. `blog` maps to `blog`, `portfolio` to `portfolio`, `project` to `projects`, and `credit` to `credits`. Drafts remain private in Firestore. Do not hand-edit the `cms` subfolders. Firebase Admin SDK uses Application Default Credentials or `GOOGLE_APPLICATION_CREDENTIALS`; set `FIREBASE_PROJECT_ID` if the project differs from `sounddesignportfolio`. For local emulator exports set `FIRESTORE_EMULATOR_HOST`.

Publishing uses the Firebase callable function and dispatches only to the fixed repository `Hyeur/hyeur.github.io`. Create a fine-grained GitHub token restricted to that repository with only Contents: write permission ([required by repository dispatch](https://docs.github.com/en/rest/repos/repos#create-a-repository-dispatch-event)), then store it in Firebase Functions Secret Manager as `GITHUB_PUBLISH_TOKEN` using `firebase functions:secrets:set GITHUB_PUBLISH_TOKEN`. Never put the token in the browser app, GitHub secrets, or source. Cloud Functions and Secret Manager require the Firebase project to use the Blaze plan; review the current billing setup before deployment. Cloud Functions uses Node.js 22. After installing the Firebase CLI and configuring that secret, deploy the callable and restrictive rules with `firebase deploy --only functions,firestore:rules,firestore:indexes --project sounddesignportfolio`.

The GitHub workflow uses the existing `FIREBASE_SERVICE_ACCOUNT_SOUNDDESIGNPORTFOLIO` repository secret containing a service account JSON key. Grant that service account Firestore access to read `entries` and update publish request status, plus permission to deploy Firebase Hosting in `sounddesignportfolio`. The workflow runs export, Hugo build, admin build, and only then Hosting deploy; failures update the request while leaving the current Hosting release live. Add or rotate the key in `Hyeur/hyeur.github.io` Settings > Secrets and variables > Actions. Do not commit the key file.
